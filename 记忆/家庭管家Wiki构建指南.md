# 家庭管家 Wiki 构建指南

这份文档是家庭管家知识库的构建和验收依据。知识库根目录为项目内的「记忆」。日常从 [Wiki 首页](wiki/index.md) 进入，维护约定见 [AGENTS.md](AGENTS.md)。

## 1. 建立目录和入口

~~~text
记忆/
├── raw/                 原件，先直接放在这里
├── wiki/
│   ├── index.md         首页
│   ├── 家庭日常/        家庭习惯、常用安排、办事流程
│   ├── 物品与设备/      收纳位置、设备说明、维修和耗材
│   ├── 健康/            授权保存的健康记录和跟进事项
│   ├── 工作/            项目、会议结论和常用工作流程
│   ├── 学习/            学习目标、资料笔记、练习与复盘
│   ├── 管家记忆/        已确认的偏好、提醒方式和长期约定
│   ├── 待办与维护.md    待办、定期维护和完成记录
│   └── 维护/
│       ├── 模板.md
│       ├── log.md
│       └── 报告/
└── scripts/             检查和本地搜索命令
~~~

Wiki 根目录的 index.md 是唯一总目录。按六个主题分组，写明各主题的用途，并为每条已入库页面添加链接和一句摘要。分类文件夹可为空，有了正文再在总索引对应分组下加链接。总待办直接从首页进入。定期维护写在总待办，来源和细节链接到对应主题。需要链接多处时保留一份正文。例如，换滤芯的记录放在「物品与设备」，下一次更换日期出现在总待办。

每张 Markdown 页面用 YAML frontmatter 写 type 和 date，日期格式为 YYYY-MM-DD。首页用 wiki-index，事项页用 tasks，普通记录用 note。模板、维护日志和报告分别使用 template、system-log 和相应的报告类型，并添加 graph-excluded: true。新记录从 [通用模板](wiki/维护/模板.md) 复制，按需填写。要补建目录，可以从「记忆」运行：

~~~sh
mkdir -p raw wiki/{家庭日常,物品与设备,健康,工作,学习,管家记忆,维护/报告}
~~~

在 Obsidian 中可以把「记忆」打开为库，便于一起浏览 Wiki 和原件。也可以单独打开「记忆/wiki」聚焦知识页面。图谱过滤框可用 `-[graph-excluded:true]`。单独的 Wiki 库已配置该过滤。

## 2. 手工记录和引用

1. 把用户提供的原件保存到 raw/，保持原件内容。需要更多分类时按材料数量拆分。
2. 从首页进入主题，把经过核对的记录写到相关页面，附原件相对链接或用户确认日期。Wiki 文件名可直接使用中文。引用有重名的页面时使用相对路径。
3. 用户明确确认的长期约定写进「管家记忆」。健康、工作等主题已有完整记录时，保留主题原页，在管家记忆中链接该页。
4. 有时间要求的跟进项加入总待办。新增、修改和删除页面时同步更新总索引中的链接和摘要。

### 明确要求记住的内容

1. 桌面应用会将完成的文字输入、语音转写、Codex 回复和本地直答原文写入 `raw/聊天记录/`。每个工作区每天写一份 Markdown，例如 `raw/聊天记录/2026-11-17.md`。每条消息以本机时间和发言者作为小标题，正文保留原文，元数据附角色和渠道。需要单独标记的内容，也可说「记住：每周五给植物浇水」，应用另存到 `raw/记忆条目/` 并显示路径。
2. 你在 Raw 中打开待入库条目，逐条确认来源、重复、冲突和敏感内容。应用会拦截明显的秘密和有明确信号的敏感资料。存在冲突时，由你决定保留或替代哪条。待入库条目不参与日常召回。
3. 由你自行挑选需要入库的消息。经你手动确认后，把整理结果写入对应 Wiki 主题，链接回 Raw 原条目。需要时手动运行 `python3 scripts/lint.py` 检查页面和链接，再运行 `scripts/qmd update` 刷新索引。

raw/、wiki/、本机 QMD 索引、Obsidian 设置和未来的记忆系统运行数据都排除在 Git 之外，由本机保存。

## 3. 配置本地检索与检查

在「记忆」下运行。QMD 需要 Node.js 22 或更新版本，检查脚本需要 Python 3.10 或更新版本以及 PyYAML。已有 PyYAML 时可以直接运行检查。

~~~sh
python3 -m venv .qmd/python
.qmd/python/bin/python -m pip install PyYAML
npm install --prefix .qmd @tobilu/qmd@2.8.3
scripts/qmd collection add wiki --name meowvis-wiki --mask '{家庭日常,物品与设备,健康,工作,学习,管家记忆}/**/*.md,待办与维护.md'
~~~

若已有同名集合且路径规则是旧版，先用 scripts/qmd collection show meowvis-wiki 核对，再用 collection remove 后重新添加。该命令清除本地索引条目，Wiki 页面保存在原目录。集合覆盖六个主题和总待办。

~~~sh
python3 scripts/lint.py
scripts/qmd update
scripts/qmd status
scripts/qmd search "关键词" -c meowvis-wiki
~~~

在虚拟环境安装 PyYAML 时，用 .qmd/python/bin/python 执行检查。报告位于 wiki/维护/报告，覆盖入口、元数据和本地链接。有问题时返回 1。QMD 的索引留在本机，当前以关键词检索为主。

### 从贾维斯查询 Wiki

在桌面直接提问，或说「查 Wiki」并带上问题。AI 判断问题是否需要已入库资料，从总索引选页，读正文后回答并给出来源。索引提供的线索不足时，可以用本地关键词检索帮助定位。语音由后台完成查阅，再播报答案和依据。

桌面查询即时读取当前工作区的 Markdown。档案使用按章查询入口。资料不足时，回答应说明 Wiki 已记录的范围；读取出错时说明具体问题。Raw 原文由用户挑选并手动入库。

## 6. 桌面读取接入（阶段 A）

| 读取入口 | 迁移前来源 | Wiki 来源 | 调用者 |
| --- | --- | --- | --- |
| 角色设定 | 根目录喵维斯设定.md | wiki/喵维斯设定.md | 新建或恢复桌面线程、语音启动、语音设定更新 |
| 用户档案 | 根目录用户档案.md | wiki/用户档案索引.md 导航到个人与家庭档案、已确认偏好、工作档案 | 档案直答、后台按章查询 |

本阶段沿用已经建立的来源、主题页与维护规则三层。首次迁移由人工核对，查询按主题读取，检查覆盖入口、文件和链接。Wiki 首页导航和档案索引只用于查找页面，运行时各自读取角色或单个档案主题。

在选定工作区，将记忆/.wiki-read-mode 的内容设为 wiki 后启用。Wiki 是维护入口。若保留了根目录原文件，可将它们作为迁移时的兼容快照。没有该标记的旧工作区继续使用根目录文件。已启用的工作区发生缺页、断链、空文件或越界时，应用报告对应文件。需要回退时，先确认根目录的迁移前文件可用，再把标记改为 legacy，并重启应用以刷新线程和语音会话。只改标记会让已移除原文件的工作区失去参考资料。

## 7. 长期记忆离线核心（阶段 B）

离线候选的策略是仅在用户明确要求时生成候选，逐条确认，只在本机使用。候选快照只放用户要求记下的陈述及来源标识。完整聊天原文独立保存在 Raw 聊天档案。离线核心只处理普通事实或偏好，敏感信息和待确认印象仍需各自的确认入口，秘密禁止保存。

- 合成完整用户消息经本地规则提取候选。例如「记住：……」或「请记住我……」。主题、类别和有效期由调用方提供。未完成转写、普通闲聊和助手回答均不能生成候选。
- 候选含来源和版本，确认前不进入召回。重试同一消息不会增加记录。同主题、同内容、同一有效期的候选可合并不同来源。
- 时间范围使用左闭右开区间。有效期重叠时，确认者须指明要替代的当前版本。过期、拒绝、争议和已替代记录不进入普通召回。
- 每个工作区的离线存储采用一个版本化快照 `记忆/记忆系统/state.json`，借助文件锁协调并发写入，同目录原子替换，避免候选、索引和处理状态之间出现半写入。根据主题即时筛选已确认记录。审核事件仅保存操作、记录号和时间。
- 按主题遗忘会移除该主题的候选、确认记录和历史版本。清空会移除全部记录。最小删除屏障只保留主题与来源摘要、时间和处理代次，以阻止旧消息和在途任务回写。重新记录同主题须有新的明确请求，再逐条确认。

实现位于 `src-tauri/src/memory/`。离线候选状态 API 尚未接入桌面会话，合成测试只在临时工作区写入。阶段 A 的档案和 Wiki 页面是现有的独立查阅入口。

桌面的聊天归档和「记住」条目保存入口都只写 Raw。Wiki 入库由用户按第 2 节手动处理。
