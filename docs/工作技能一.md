# 工作技能一：腾讯文档与企业微信跟进核对

## 调用

用户说“执行工作技能一”或“执行工作 技能一”时，先阅读本文，再执行本次指定范围；未限定人数时处理当前目标表内所有符合条件的用户。用户临时说明优先。

### 默认直接执行并回填

- 用户说“用技能一看一下某人的聊天记录”“用技能一处理某人”等，也视为调用完整流程：核对聊天 → 判断状态 → 生成草稿 → 写入对应行第六、七列 → 验证保存；不是仅在对话中汇报。
- 除非用户明确说“只看不写”“先讨论”“先给我看草稿”，否则不先口头复述分析或草稿，不再追问是否写表格；完成回填后只简短报告已写入、未发送及必要限制。
- 用户在技能一执行过程中明确修改回复口径时，直接按新口径更新对应草稿并验证保存，无需再次征求写表确认；仍不发送消息。
- 找不到表格或对应行、身份不明、目标状态属于跳过项或存在无法确定是否可覆盖的人工内容时，说明具体阻碍并仅询问必要信息，不擅自新增用户行、覆盖人工内容或把未回填报告为完成。

## 目标与边界

从腾讯文档第一列取得用户名称，在企业微信匹配对应项目群，阅读上下文，判断交流状态，生成简短、有礼貌、贴合需求的回复草稿，写回原用户行供人工审核。

- 默认目标为用户当前打开的“799许愿池”；每次核对实际窗口与表名，不能仅凭上次画面写入。目标不清楚时询问。
- 跳过原状态为“未建联”、“进行中”“已抛弃”的用户；其余状态均核对。不得自行扩大跳过条件。
- 前五列保持原样；仅操作第六列及以后，不排序、不删除、不改变筛选或分享权限。
- 当前约定第六列“核对状态与摘要”，第七列“回复草稿（未发送）”。摘要内合并需求、进展、下一步、依据和核对日期，无需新增五列。
- 用户自行逐条审核、决定是否回复并亲自发送；技能调用不授权发送企业微信消息，也不把草稿标为已发送。
- 不另外创建待办清单、不主动反复询问是否排序或发送。

## 执行流程

1. 观察当前表格，确认名称、原状态、可编辑列和总行数，逐段查看直到末尾，不能把首屏当成全部。
2. 按范围逐个搜索企业微信名称，优先项目专属群；私聊无记录不代表群里无记录。遇同名，结合群名、成员和表内需求核对，无法确定就标“身份/记录待核对”，不混用他人聊天。
3. 阅读最近完整交流及必要的更早需求，识别家长与实际使用者、团队成员的角色。遇“方案1/2”等必须读回所指内容，不单凭最后一句判断。
4. 判断当前在等谁：用户考虑或补材料、我方方案/调研/测试反馈、双方约会、我方需回答遗漏问题、旧方案需按澄清修订、信息不足。已解释或已回应的不硬判为漏回；我方说“收到/稍后整理”不等于完成交付。
5. 摘要写明可见依据的群名与时间、下一步，以及未核验的附件、图片或视频。不要假装读过附件；必要时另行核验，无法核验则明确限制。时间以实际系统与消息日期为准，避免把相对日期写成错误绝对日期。
6. 草稿回应具体想法，简短自然，不堆术语；需要等待时坦诚说明安排较满，但不编造已经开展的工作、不承诺日期或功能。用户已选方向不重新替其选题；已否定方案不继续沿用。等用户考虑时不一律发送排队模板，尊重其“先不打扰”的意愿，可标备用稿。
7. 只把结果写入正确用户行第六、七列；已有非本技能内容不覆盖。再次执行时保留人工审核改动，无法识别能否覆盖就询问；旧技能结果需更新时保留必要依据并以新核验为准。
8. 验证单元格内容、对应行及保存状态。发生超时后重新观察已落盘内容，不能盲目重放。结束报告实际完成、跳过、待核对数量及限制，不把未读或未写行算完成。

## 输出样式

第六列：建议状态：……；需求与最近进展：……；下一步：……；依据：对应群最近相关消息日期及范围；限制：……；核对日期：……。

第七列：一条可直接供用户审阅的回复草稿；不在客户草稿中加入助手对用户的“先生”称呼习惯。无需回复时写明“暂无必须回复；以下为备用稿”或“当前不建议打扰”。

## 隐私与操作要点

- 仅摘录任务需要的信息，不把完整聊天或孩子健康、家庭等敏感细节复制到表格，不记录账号密码；敏感内容跨服务传输须遵守当次授权。
- 通过当前可用的专用连接器或获准的界面工具操作；使用界面工具时遵循其观察、操作、再观察及完成总结要求。
- 腾讯文档小程序可能归属微信应用；网页没有无障碍表格内容时可用截图核对。企业微信搜索可能需回车才打开群；原生输入无效时核对焦点后再尝试粘贴。
- 不保存固定坐标或无障碍索引供下次盲用，每次从新画面定位。当前没有实现自动定时运行；文档与调用入口不等于后台自动化。
