# 会话保存与恢复

本版以工作目录隔离会话，语音连接不再等于一次独立聊天。正常停止、重新唤醒和重启应用会续接当前会话；只有明确要求开启新会话或恢复指定历史会话时才切换。

- 语音上下文：本机保留最近 80 条、约 100000 字符内的消息，以及最近一次任务的请求、状态和结果。重新连接时向千问提供最多最近 24 条、16000 字符内的对话和任务状态。长对话更早的逐字细节不保证自动恢复，完整 Raw 归档另行保留。
- 任务上下文：保存 DeepSeek Harness 返回的真实会话 ID。下一次明确执行任务时调用 SDK 的 `resumeSession` 恢复，不以新会话冒充恢复成功。
- 中断处理：上次运行中的任务在重启后标为中断，只恢复上下文，不自动继续执行、重试或撤销文件操作。任务历史恢复失败会明确报告，需要重新连接或明确开启新会话。
- 会话控制：自然语言由 `conversation_session` 工具处理。支持“开启新会话”“列出历史会话”和选择历史会话后恢复。任务运行时不允许切换会话。
- 保存位置：应用数据目录下 `deepseek/desktop-sessions/<工作目录摘要>/`，使用私有权限、临时文件原子替换和顺序写入。SDK 自己的任务历史继续位于原 Harness home。API Key 不作为会话配置保存。
- Wiki：长期记忆和会话续接互相独立。开启新会话不会删除 Wiki；恢复会话也不会自动把聊天入库。
- 桌面连接已去除原有 30 分钟测试断开限制；网络或上游断开后仍需重新唤醒，重新连接会加载已保存的当前会话。

此机制从新版首次连接开始保存会话，不会猜测旧版未关联会话 ID 的任务，也不会自动扫描旧 Raw 作为新会话上下文。

验证包括本地持久化与工作区隔离测试、停止与恢复失败测试，以及 `runtime/desktop-voice/node scripts/check-session-runtime.mjs` 的真实 SDK 进程关闭与恢复测试。语音措辞与真实任务的连续追问仍应在桌面端验证。
